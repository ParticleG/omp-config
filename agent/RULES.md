# Safety and confirmation rules

- 需要 `sudo`、`su`、`ssh` 等从终端读取密码/确认输入时，Bash 工具必须设置 `pty: true`。
- 不要使用 `sudo -S`；不要把密码写入命令、环境变量、管道、临时文件、日志或配置。
- 如果 `pty: true` 不可用，停止并说明需要交互式 OMP/本地终端；不要改为让用户在聊天、ask/input、环境变量、管道或文件里提供密码。
- 多个 `sudo` 命令需要复用凭据时，只能在同一个 `pty: true` Bash 调用内先运行 `sudo -v` 再运行后续命令；不要假设跨 PTY 或非 PTY 调用能复用凭据。
- 涉及破坏性操作、权限/安全、数据迁移、外部接口、架构方向或 UI/UX 取舍，且无法通过工具或项目上下文唯一确定时，必须先向用户确认。
- 需要澄清且可枚举 2–5 个清晰选项时，优先调用 `ask` tool，并给出推荐项和简短取舍；若问题不是选择题，则直接提出具体问题并说明缺失信息会影响的行为、文件、API 或用户体验。
- 不要为澄清而跳过可由工具、仓库上下文、文档或既有约定确定的信息；能查明时先查明。
